# StockCausal 项目复盘 · 2026-11-20

> 这不是流水账。它回答五个问题：**要解决什么、做成了什么、用了什么方法、背后的思想是什么、还缺什么。**

---

## 一、这个项目要解决什么

**用户原话**：

> 「我的目的是看过往**资金**对接下来股票涨跌的影响，一切以资金为本，发现资金异动。」

翻译成一个可验证的命题：

> 历史上出现「资金异动」的股票，之后（T+1，参考 T+3）的收益是否**系统性**高于同期同行？

三层目标：

| 层 | 目标 | 达成与否 |
|---|---|---|
| 数据层 | 每日把资金痕迹自动落成本地数据 | ✅ |
| 检验层 | 能把一条「资金 → 涨跌」的说法算成一个数 | ✅ |
| 决策层 | 通过检验的说法进模拟盘 | ❌ 还没到 |

**明确不做**（写在这里防止跑偏）：不预测、不荐股、不做全市场、不碰高频、不给交易信号。

## 三、用了什么方法

### 3.1 数据采集

| 问题 | 方法 |
|---|---|
| 五个源的口径不一样 | **混源取数 + 每行标注「数据来源」**，统计前按来源筛 |
| 同花顺反爬（翻页 401） | 只取服务端直出的首页；历史改用东财 |
| 东财限流（连发封 IP） | 单源限速 0.35s、失败退避 1/3/7s、只做单只兜底 |
| 同花顺 502/504 偶发 | 重试 3 次；日期对不上就切东财 |
| 批量回补会中断 | 按日期幂等写入 + 断点续传（已落盘的日期跳过） |
| 系统代理指向死端口 | 所有请求走空 `ProxyHandler` 直连 |

### 3.2 统计方法

| 环节 | 做法 | 为什么 |
|---|---|---|
| 收益定义 | T 日收盘得信号 → **T+1 开盘买、收盘卖**；减同日上证收益 | 用 T 日收盘价成交 = 未来函数 |
| 可交易性 | 剔除 T+1 开盘涨停、一字板 | 买不进的收益是假收益 |
| 标准化 | 每只股票自己的 z-score，**只用样本内**估计均值/方差 | 用全样本 = 未来数据泄漏 |
| 分档 | 五分位，**边界只用样本内**算 | 否则样本外自己定义档位 |
| 标准误 | 先算每日横截面均值，再对**日序列**做 t 检验 | 同一天 30 只票一起动，样本不独立 |
| IC | 每日横截面 Spearman，再对日序列看 t | 与分档互相印证 |
| 样本内外 | 70/30 时间切分，**按每个指标自己有数据的交易日切** | 按价格日历切会让样本内为空 |
| 判定 | 跨档差 > 0.1pp **且** 最优档扣成本为正 **且** \|rho\|≥0.8 **且** 极端档 \|t\|≥2 **且** 每档≥100 | 只看跨档差会被 U 形噪声骗过 |

### 3.3 工程方法

| 原则 | 实现 |
|---|---|
| 幂等 | CSV 按「交易日整段替换」，重跑不产生重复行 |
| 防呆 | 取到 0 行不清空旧数据；同日行数骤减拒绝覆盖；先写临时文件再原子替换 |
| 可追溯 | 每次分析追加写入 `experiments.db`（含股票池指纹、数据截止日、参数 JSON） |
| 可自查 | `status.py` 看数据进度，`analyze_features.py` 看结论，都不依赖 AI |
| 可复现 | 同一份数据 + 同一套参数 = 同一份结果，报告存 `reports/` |

## 四、背后的思想

1. **先定义能被证伪的问题，再写代码。**
   否则会写出「能算但不知道要算啥」的工具（这次就犯过：先写 analyze.py，跑成了价格自相关）。

2. **口径写在列名里，不给换算留空间。**
   `成交金额(亿元)`、`融资余额(元)`、`涨跌幅(%)`——单位进列名，就不会有人把「元」当「万元」。

3. **混源必须标注来源，不混着统计。**
   同花顺 86 行 vs 东财 95 行不是谁错，是口径不同；标出来才能筛。

4. **判定线先定死，跑完不许改。**
   改了就是把答案迁就自己（p-hacking）。

5. **样本内外严格隔离。**
   标准化、分档、阈值、选参数，全都只能用样本内。

6. **宁可报 FAIL，也不报一个扛不住质疑的 PASS。**
   这次差点把 U 形噪声报成「资金有效应」——工具跑通 ≠ 结论可靠。

7. **失败记录和成功记录一样重要。**
   台账里失败的实验防止半年后重跑同一个想法。

8. **用户必须能自己看到进度和结果。**
   长任务不能只跑在 AI 的后台里，要给一条自己能执行的命令。

9. **能便宜验证的，先用便宜的。**
   判断「有没有效应」只需要日频数据，不需要 Level-2、不需要分钟线。

## 五、还缺什么

按优先级：

| # | 缺什么 | 影响 | 补法 |
|---|---|---|---|
| 1 | **样本外只有 50~56 个交易日** | 结论不可信，任何 PASS/FAIL 都可能是偶然 | 回补到 2~3 年（再 1.5~2 小时） |
| 2 | **龙虎榜指标样本太稀**（30 只一年约 110 次上榜） | 3 个事件型指标完全测不了 | 股票池扩到 100~200 只 |
| 3 | **日线缺成交额** | 「净买占成交额比」类指标算不了 | 东财逐股补 amount 列 |
| 4 | 两融市场总量只有 10 个交易日 | 市场层杠杆环境缺失 | 交易所官网另写解析 |
| 5 | 深交所 ETF 份额无历史 | 只有沪市能回补 | 深交所有「基金规模」报表，限 6 个月，待验证 |
| 6 | 定时任务未设 | 数据靠手动跑 | 任务计划程序调 python.exe |
| 7 | 样本只含活着的股票 | 幸存者偏差，结论偏乐观 | 短期无法解决，结论里要标注 |
| 8 | 没有模拟盘 | 无法验证「扣完成本真能赚」 | 等有 PASS 再说 |

## 六、复盘：决策对错

| 决策 | 判断 | 证据 |
|---|---|---|
| 不做纯同花顺、混源取数 | ✅ | 同花顺缺 ETF 份额、大宗只给 50 笔、两融只给前 50 |
| 日线存 SQLite | ✅ | 22,415 行 3MB；事件 CSV 已 100MB+ |
| 自选池 + 近 3 年，不做全市场 | ✅ | 全市场 2.7 小时，当前用不上 |
| 股票只取不复权 | ✅ | 前复权把 1790 记成 1636 |
| **判定只看跨档差** | ❌ | U 形噪声被判 PASS（假 +0.34pp） |
| **按价格日历切样本内外** | ❌ | 回补只有 1 年 → 样本内几乎为空 |
| **先写分析脚本再定指标** | ❌ | 跑成价格自相关，方向不对，白费一轮 |

## 六、复盘：踩的坑

| 坑 | 谁发现 | 修法 |
|---|---|---|
| 前复权污染 | 我 | 股票只用 seg=00，前复权只给指数 |
| 方向跑偏（价格 ≠ 资金） | **用户** | 重做资金指标，价格版留作对照 |
| 判定被 U 形骗 | 我 | 加单调性 / 极端 t / 最小样本 |
| 样本内外切错 | 我 | 按指标自身可用日期切 |
| 项目名改三次 | 用户 | ths-daily → StockCausual → StockCausal |
| 方案太长两次被驳回 | 用户 | 改成分步给、先答后给方案 |

**两个真正的失误**：

1. 没先确认「要检验什么」就动手写分析 → 白跑一轮。
2. 判定规则太松 → 差点把一个假结论交给用户做决策。

## 八、一句话总结

**今天最大的产出不是「跑出了什么结论」，而是「一套不会再骗自己的检验流程」——它会稳定地告诉你 FAIL，这比给你一个漂亮的 PASS 有价值。**
